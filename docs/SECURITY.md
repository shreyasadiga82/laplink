# Security & Threat Model

LapLink provides root-level access to the host machine, making security the absolute highest priority.

## Threat Model
1. **Network Eavesdropping:** Attacker snoops traffic.
2. **Relay Compromise:** The Cloudflare Worker is compromised or hijacked.
3. **Unauthorized Access:** Attacker attempts to brute-force signaling.
4. **Agent Exploitation:** Buffer overflows or memory exploits in the Agent.

## Mitigations

### End-to-End Encryption (E2EE)
- **WebRTC DTLS-SRTP:** All video and audio streams are encrypted natively.
- **DTLS Fingerprint Validation:** The signaling channel sends WebRTC SDPs. To prevent a compromised Worker from MITMing the DTLS handshake, the Agent and Client derive a shared secret using `Argon2id` from a manually-entered passphrase. They compute an HMAC of the DTLS fingerprint. If the fingerprint doesn't match the HMAC, the connection is instantly aborted.
- **DataChannels (Control/Files):** Encrypted using `libsodium` (XChaCha20-Poly1305) with keys derived from the same `Argon2id` passphrase. 

### Device Enrollment
- The Cloudflare Worker keeps a list of authorized device public keys.
- To enroll a new device (tablet/phone), an enrollment code is generated by the owner via the `enroll.py` CLI or an already trusted device. 
- The Worker will completely drop and ignore WebSocket connections that are not signed by an enrolled device key. There is no public login page or banner.

### Cloudflare Worker
- The Worker only sees ciphertext (for Control/Files) and metadata (SDPs, ICE candidates).
- Even if the Worker is fully compromised, the attacker cannot read the screen, inject input, or decrypt files.

### Least Privilege
- The Windows Agent requires high privileges (Scheduled Task at logon) to capture the screen and inject input. 
- Input injection drops all held keys if the connection drops.
- Destructive actions (Shutdown, Delete File) require explicit secondary confirmation.
